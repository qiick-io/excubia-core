# Changelog

All notable changes to **Excubia** (`qiick/excubia-core`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Laravel Scout (#221): new runtime aggregate type `scout`, off by default, switched by the new `excubia.json` key `runtime.scout` (`enabled`, `sampleRate`), recorded only when `laravel/scout` is installed (`class_exists`; it is not a dependency, and the tests fake it under its real class names). One entry per `model` (class), `engine` (`scout.driver`, `unknown` unless it is 1 to 64 characters of `A-Z a-z 0-9 _ . -`) and `operation`. Scout fires no event when it updates an index or runs a search, so `index` and `remove` are its queued index jobs (`MakeSearchable`, `RemoveFromSearch`, their subclasses and the classes set with `Scout::makeSearchableUsing()` / `removeFromSearchUsing()`, run when `scout.queue` is on), with `count`, `errorCount` (failed jobs), `modelCount` (records carried, the length of the serialized key list), `totalMs`, `maxMs` and the latency histogram from `JobProcessing` to `JobProcessed` or `JobFailed`; `search` counts the search builders the container makes (`Model::search()`), with no duration. Synchronous index updates (`scout.queue` off) and search latency are not observable without wrapping Scout's builder or engines, and are not recorded. Never the search query, record ids or keys, or record data.
- Laravel Sanctum and Passport API tokens (#219): new check `laravel-api-tokens`, appended to the run order, and new runtime aggregate type `auth`, off by default, switched by the new `excubia.json` key `runtime.auth` (`enabled`, `sampleRate`). Neither `laravel/sanctum` nor `laravel/passport` is a dependency (`class_exists` plus their merged config; the tests fake their classes under their real names and create their tables with the packages' own migrations). `laravel-api-tokens` is Artisan only, one set of rows per installed package. Sanctum: `sanctum.expiration` null while some token has no `expires_at` (low, medium in production), tokens not used for 90 days (`last_used_at`, or `created_at` for a token never used; low), and in production a `stateful` entry with a wildcard (medium) or no domain (low); details `provider`, `expirationMinutes`, `hasStatefulWildcard`, `isStatefulEmpty` and the counts `tokenCount`, `nonExpiringTokenCount`, `staleTokenCount`, `neverUsedTokenCount` of the still-valid tokens in `personal_access_tokens` (null when the table is missing). Passport: no keys (high in production, medium elsewhere), a private key file mode other than 0400, 0440, 0600, 0640 or 0660 (high in production, low elsewhere), access tokens over 30 days or refresh or personal access tokens over a year (low); details `provider`, `hasKeys`, `isPrivateKeyTooOpen`, the three lifetimes in minutes and `personalAccessClientCount` (active personal access clients in `oauth_clients`, Passport 12 and 13 schemas). Read-only queries with the probe's 3 s connect timeout and a 3 s statement timeout on MySQL and PostgreSQL. Never a token, a token name or ability, a user id, a key, a path or a domain. `auth` has one entry per `guard` with `count`, `errorCount` (failed logins, `Failed`), `loginCount` (`Login`), `lockoutCount` (`Lockout`, which carries no guard and counts under `auth.defaults.guard`) and `tokenAuthenticationCount` (Sanctum's `TokenAuthenticated`, guard `sanctum`; Passport fires no event when a token authenticates a request). Never usernames, emails, user ids, credentials, tokens or IP addresses. Benchmark: about 0.005 ms per authentication event. Additive: `x-excubia-version`, `schemaVersion` and `protocolVersion` stay `1`.
- Laravel Cashier billing webhooks (#217): new runtime aggregate type `billingWebhook`, off by default, switched by the new `excubia.json` key `runtime.billing` (`enabled`, `sampleRate`), and the new check `laravel-cashier`, appended to the run order. Both act only when `laravel/cashier` (Stripe) or `laravel/cashier-paddle` is installed (`class_exists`); neither is a dependency (the tests fake their classes under their real names). `billingWebhook` has one entry per `provider` (`stripe`, `paddle`) and `eventType` (the provider's event type, such as `invoice.payment_failed`, kept only when it is 1 to 64 characters of `a-z 0-9 _ .`, else `unknown`), from Cashier's `WebhookReceived` and `WebhookHandled`: `count` (received), `handledCount`, `errorCount` (the request ended with a 5xx before Cashier's handler returned: the provider retries), `totalMs` / `maxMs` / `histogram` (handling time), and the payment signals `paymentFailedCount` (Stripe `invoice.payment_failed`, Paddle `transaction.payment_failed`), `paymentActionRequiredCount` (Stripe `invoice.payment_action_required`, Paddle `subscription.past_due`) and `subscriptionCanceledCount` (Stripe `customer.subscription.deleted`, Paddle `subscription.canceled`). Never anything else of the payload: no amounts, currencies, customer or subscription ids, emails or cards. `laravel-cashier` is Artisan only, per installed package: no webhook secret (high in production, low elsewhere: Cashier then skips the signature check), test keys in production (high, from the key prefix or Paddle's sandbox flag) and no route to Cashier's webhook controller (medium), else one info row; details `provider`, `isWebhookSecretConfigured`, `isWebhookRouteRegistered` and `hasTestKeys`, booleans only, never a key, secret or prefix. Benchmark: about 0.007 ms per webhook. Additive: `x-excubia-version`, `schemaVersion` and `protocolVersion` stay `1`.
- Laravel Reverb (#215): new runtime aggregate type `reverb`, off by default, switched by the new `excubia.json` key `runtime.reverb` (`enabled`, `sampleRate`), and the new check `laravel-reverb`, appended to the run order. Both act only when `laravel/reverb` is installed (`class_exists`); it is not a dependency (the tests fake its events under their real names). `reverb` is recorded in the `reverb:start` process, one entry per `server` (as for `server`) and `appId` (the Reverb app id, hashed when it is not a short name), from `MessageReceived`, `MessageSent`, `ConnectionPruned`, `ChannelCreated` and `ChannelRemoved`: `messagesReceived`, `messagesSent`, `connectionsOpened` (`pusher:connection_established` sent), `connectionsRejected` (`pusher:error` before that: quota or origin), `errorCount` (other `pusher:error` frames), `connectionsPruned`, channels created and removed by prefix (`public…`, `private…`, `presence…`), and `maxConnections`, the subscribed connections sampled once a minute by a 60 s timer Excubia adds to Reverb's event loop, which also flushes the buffer that `excubia:push-runtime` reads. Reverb has no event for a connection a client closes. Never message payloads, event or channel names, socket ids, origins, app keys or secrets. `laravel-reverb` is Artisan only: when Reverb is the default broadcast driver, a TCP connect (2 s timeout) to its configured host and port, one info row with the connect time, or a high failure when nothing answers; details `isReachable` and `latencyMs`, never the host or port. Skipped without Reverb, when it is not the broadcast driver or names no host. Benchmark: about 0.005 ms per Reverb message. Additive: `x-excubia-version`, `schemaVersion` and `protocolVersion` stay `1`.
- Laravel Octane workers (#213): new runtime aggregate type `octane`, off by default, switched by the new `excubia.json` key `runtime.octane` (`enabled`, `sampleRate`), and the new check `laravel-octane-config`, appended to the run order. Both act only when `laravel/octane` is installed (`class_exists`); it is not a dependency (the tests fake its events under their real names). `octane` has one entry per `server` (as for `server`), `octaneServer` (`swoole`, `roadrunner`, `frankenphp`, `unknown`) and `workerType` (`http`, or `task` for a Swoole task worker), from `WorkerStarting`, `RequestReceived` / `RequestTerminated`, `TaskReceived`, `TickReceived`, `WorkerErrorOccurred` and `WorkerStopping`: `workerStarts`, `workerStops`, `requests`, `tasks`, `ticks`, `errorCount` (worker errors), `maxMb` (memory in use after a request) and `maxGrowthMb` (its growth since the worker's first request, the leak signal), and `totalRequestsAtStop` / `maxRequestsAtStop` (requests a worker handled before it stopped, to compare with `max_requests`). Never URLs, request, response or task data, exception messages, worker ids or PIDs. `laravel-octane-config` is Artisan only: one info row with the server type, and in production a warning when `octane.max_requests` is unset (low) or 0 (medium); details `server` and `maxRequests`. Benchmark: about 0.01 ms per request and tick. Additive: `x-excubia-version`, `schemaVersion` and `protocolVersion` stay `1`.
- License kind in `dependency-licenses` details (#204): each finding's `details` carries `kind`, `denied`, `copyleft` or `unknown`, so an app no longer infers it from status and severity. Optional in `docs/report-schema.json`; `schemaVersion` stays `1`.
- App environment in reports and runtime batches (#203): an optional `environment`, the Laravel environment (`app.env`) such as `production` or `staging`, in the report from `php artisan excubia:check` and `excubia:push` (the standalone CLI cannot boot the app and omits it) and in each runtime batch (`runtime.environment`). Only a short name of 1 to 64 `A-Z a-z 0-9 _ -` is sent; anything else, a hostname included, is omitted. Exception groups already carried `environment`. Additive: `x-excubia-version` and `protocolVersion` stay `1`.
- Classification in the `ai` runtime type (#201): the Laravel AI SDK's `Classifying`, `Classified` and `ClassificationFailed` (laravel/ai 1.3) are recorded as `operation` `classification`, timed through the invocation id like the other operations, with failovers and the `TextUsage` counts. Never the classified text or data, the questions or the answers. Additive: a new `operation` value, `x-excubia-version` and `protocolVersion` stay `1`.
- The scheduler heartbeat cache key is a documented contract (#205): `docs/CONTRACTS.md` lists `excubia:scheduler-heartbeat` with its value format (integer Unix time in seconds, no expiry, overwritten every run), and a contract test keeps the doc, the constant and the stored value in sync. No behaviour change.
- Laravel AI SDK usage (#198): new runtime aggregate types `ai` and `aiTool`, off by default, switched by the new `excubia.json` keys `runtime.ai` and `runtime.aiTools` (`enabled`, `sampleRate`). Active only when `laravel/ai` is installed (`class_exists`); it is not a dependency (dev-only, for the tests). `ai` is keyed by `operation` (`agent`, `image`, `embeddings`, `transcription`, `reranking`, `audio`), `agent` (agent class, agent operations only), `provider` and `model`, timed from `PromptingAgent` / `StreamingAgent` / `Generating…` / `Reranking` to the done or failed event through the invocation id, with `count` (provider attempts), `errorCount`, `failoverCount` (`AgentFailedOver`, `ProviderFailedOver`), `totalMs`, `maxMs`, the latency `histogram` and the usage counts `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheWriteInputTokens`, `reasoningTokens`, `imageInputTokens`, `imageOutputTokens`, `audioSeconds` and `searchUnits`: null when the provider does not report them, summed on merge, null only when every entry is null. A stream is counted once, at `AgentStreamed`, with its final usage. `aiTool` is keyed by `agent` and `tool` class, from `ToolInvoked` / `ToolFailed` with the SDK's own duration. No cost in core: the app computes it from the tokens. Never prompts, instructions, attachments, messages, response text, reasoning, tool arguments or results, conversation ids or users, or exception messages. Benchmark: about 0.02 ms per agent run with one tool call. Additive: `x-excubia-version` and `protocolVersion` stay `1`.

### Fixed

- `--format=json` and `--format=sarif` no longer print the banner before the report (#197), in `vendor/bin/excubia check` and `php artisan excubia:check`: stdout of a machine-readable format is the report alone and parses as-is, with or without `--no-banner`. `table` and `markdown` keep the banner unless `--no-banner` is passed. No option, exit code or report change.
- `vendor/bin/pest --group=benchmark tests/Laravel/RuntimeOverheadBenchmarkTest.php` passes when run on its own (#202): the `bufferedRuntime()` and `bufferedOfType()` test helpers moved from `RuntimeMonitoringTest.php` to `tests/Pest.php`. Tests only.

## [1.0.0-beta.3] - 2026-11-07

Third beta of 1.0 (D20), additive to the contracts frozen in 1.0.0-beta.1 ([`docs/CONTRACTS.md`](./docs/CONTRACTS.md)). The new `health` runtime type is off by default; schema and protocol versions stay `1`.

### Changed

- The `mail` runtime type counts failed sends without exception capture (#175): a `MessageSending` with no `MessageSent` by the end of its scope (the next send, the end of a queued job or attempt such as a failed `SendQueuedMailable`, the end of an Artisan command, or terminate) is one failed mail. This is now the only source of mail failures: the exception capture hook no longer counts them, so a send is counted once with capture on, and a reported transport exception without a `MessageSending` (a Symfony transport used directly) is no longer counted as an `unknown` mail. Limits are in the runtime monitoring guide. No field, config key or schema change; `x-excubia-version` and `protocolVersion` stay `1`.

### Added

- Minute-level health samples for failure alerts (#188): new runtime aggregate type `health`, off by default, switched by the new `excubia.json` key `runtime.health` (`enabled`, `sampleRate`, `checks`, `checkBudgetMs`, `totalBudgetMs`). At most once per UTC minute on each server, `excubia:push-runtime` runs the checks of `runtime.health.checks` (default `laravel-database`, `laravel-cache`, `laravel-storage`, `laravel-disk-space`, `laravel-queue-backlog`, `laravel-queue-workers`, `laravel-scheduler-heartbeat`, `laravel-redis-memory` and `laravel-maintenance-mode`; no other id is allowed) one at a time with only the local probes each reads, never a data source, and appends one aggregate per check: `server`, `checkId`, `status`, the most serious `severity`, `findingCount` and the `fingerprints` of its warn and fail findings (the report's `fingerprint`), never a message. A check starts only while `checkBudgetMs` (default 3000) is left of `totalBudgetMs` (default 15000) from the start of the run; later checks and checks whose probe throws are sent as `skipped`, and the push always goes on. On merge the worst status wins (fail > warn > pass > skipped), the most serious severity and the larger `findingCount` win and fingerprints are the union. Additive: `$defs.health` in `docs/runtime-schema.json`, versions stay `1`.

## [1.0.0-beta.2] - 2026-11-06

Second beta of 1.0 (D20): features competitors already have, all additive to the contracts frozen in 1.0.0-beta.1 ([`docs/CONTRACTS.md`](./docs/CONTRACTS.md)). New check ids are appended to the run order; every new runtime type is off by default; schema and protocol versions stay `1`.

### Changed

- `laravel-cors-wildcard` no longer warns on `*` without credentials, Laravel's stock CORS config (#139). It fails only for `*` with `supports_credentials`.

### Added

- Log channel on `logLevel` aggregates (#174): with `runtime.logLevels` on, each entry also carries `channel`, the name of the configured logging channel that wrote it; a stack reports the stack's name, not the channels inside it. Excubia appends a `tap` to every channel in `logging.channels` (the app's own taps are kept and run first) and watches the channels already resolved; the tap pushes a Monolog processor that remembers the name for the next `MessageLogged`, which Laravel fires after Monolog ran the processors. The record, message and context are never read or changed. On-demand channels (`Log::build()`, `Log::stack([...])`) and a `MessageLogged` fired by hand have no `channel`. About 0.0002 ms per log entry (`vendor/bin/pest --group=benchmark`). Additive: optional field, no new config key; `x-excubia-version` and `protocolVersion` stay `1`.
- Container-aware server metrics (#173): inside Docker or Kubernetes, the `server` runtime aggregate now reads the cgroup limits at `/sys/fs/cgroup` (v2 `memory.max`, `memory.current`, `cpu.max`, else v1 `memory.limit_in_bytes`, `memory.usage_in_bytes`, `cpu.cfs_quota_us` / `cpu.cfs_period_us`) besides `/proc`, which shows the host there. With a memory limit, `memoryUsedMb` and `memoryTotalMb` are the container's (usage minus inactive page cache, out of the limit). Two new optional fields: `cpuLimit`, the CPU quota in cores (a nullable gauge, possibly fractional such as `1.5`; the larger value wins on merge), and `isContainer`, true when a memory limit or CPU quota applies (a boolean metric field, true wins on merge, missing counts as false). `cpuCores` stays an integer with its meaning unchanged. No limit (`max`, `-1`, the v1 unlimited value) keeps the host readings. The cgroup path is never sent. Additive: `x-excubia-version` and `protocolVersion` stay `1`.
- Two more upgrade plan steps (#176), appended after the existing ones in this order: "Update npm packages to the latest patch: …" for the `npm-outdated` packages behind on a patch without an `npm-advisories` finding (the npm twin of the Composer step from #150), then "Review dependency licenses: denied for …; strong copyleft for …." when `dependency-licenses` has a `fail` row (a denied license), naming the denied packages and any strong copyleft ones; unknown licenses are left out. Steps carry package names and versions only. Additive: the `upgradePlan` JSON shape is unchanged (only steps are added), no check id, config key or schema change; `schemaVersion` stays `1`.
- New check `laravel-backups` (#171), appended to the run order, run by `php artisan excubia:check` and `excubia:push` and `skipped` ("requires Artisan") in `vendor/bin/excubia`, like spatie/laravel-health's `BackupsCheck`: when spatie/laravel-backup is installed (detected with `class_exists`, not a dependency) it reads each destination of `backup.monitor_backups` (or of `backup.backup.destination.disks` when nothing is monitored) through the package's `BackupDestination` API. A destination without backups, one that cannot be reached, or whose newest backup is older than the new `excubia.json` key `checks.laravel-backups.maxAgeHours` (default 26) fails at high; a newest backup less than half the size of the previous one warns at medium. One row per destination, subject the disk name. Skipped without spatie/laravel-backup or without a configured destination. New report `details` `disk` (the filesystem disk name, never a root, bucket or credential), `ageHours`, `sizeMb`, `count`; SARIF location `config/backup.php`. All additive (schema versions stay `1`).
- New checks `laravel-database-connections` and `laravel-database-size` (#169), parity with spatie/laravel-health `DbConnectionCountCheck`, `DbSizeCheck` and `DbTableSizeCheck`, appended to the run order, run by `php artisan excubia:check` and `excubia:push` and `skipped` ("requires Artisan") in `vendor/bin/excubia`. `laravel-database-connections` counts the open connections of the default connection (`Threads_connected` on MySQL / MariaDB, `pg_stat_activity` rows for the database on PostgreSQL; other drivers skipped): more than `checks.laravel-database-connections.warnAt` (default 50) warns at medium, more than `failAt` (default 100) fails at high. `laravel-database-size` reports the size of the default database in MB (`information_schema` on MySQL / MariaDB, `pg_database_size` on PostgreSQL, the file size on SQLite) with its five largest tables as a pass row at info, and warns at medium above `checks.laravel-database-size.warnAtMb` (unset by default). Read-only queries on a connection opened with the 3 s probe timeout; any failure skips. New `details`: `connection`, `connectionCount`; `connection`, `sizeMb`, `largestTables` (`{table, sizeMb}`, table names cut to 64 characters). Never the database name, host or file path. Additive: new check ids appended, new optional `details` and config keys; schema versions stay `1`.
- New check `laravel-redis-memory` (#170), parity with spatie/laravel-health `RedisMemoryUsageCheck`, appended to the run order, run by `php artisan excubia:check` and `excubia:push` and `skipped` ("requires Artisan") in `vendor/bin/excubia`. It reads `INFO memory` (`used_memory`, `maxmemory`, `maxmemory_policy`, nothing else) on each Redis connection the default cache store, the default queue connection or the session use, through Laravel's Redis connection (phpredis and Predis reply shapes), or on the new `excubia.json` key `checks.laravel-redis-memory.connections` instead. One row at most per connection (subject the connection name): used memory at `checks.laravel-redis-memory.failAtPercentUsed` (default 90) of `maxmemory` or more fails at high, at `warnAtPercentUsed` (default 80) warns at medium; `maxmemory` 0 (unbounded) or the `noeviction` policy on the cache connection warns at low. Skipped when no Redis connection is used or none answers (reachability stays with `laravel-cache`). New report `details` `connection`, `usedMb`, `maxMb` (`null` when unbounded), `policy`; never a host, port or password; SARIF location `config/database.php`. All additive (schema versions stay `1`).
- New checks `php-opcache` and `php-production-ini` (#172), appended to the run order after `laravel-redis-memory`, run by `php artisan excubia:check` and `excubia:push` and `skipped` ("requires Artisan") in `vendor/bin/excubia`, like Enlightn's OPcache and php.ini analyzers. `php-opcache`: OPcache disabled in production warns at medium, `opcache.validate_timestamps` on in production warns at low, and a hit rate under 90 % or more than 90 % of the OPcache memory used warns at low. `php-production-ini` (production only): `display_errors` on fails at high, `expose_php` on and `log_errors` off warn at low. Artisan runs on the CLI SAPI, whose ini settings differ from the web server's, so both read only the web-SAPI snapshot that the health endpoint stores on an authenticated request, at most once an hour, under the cache key `excubia:php-runtime:web` (booleans, percentages, a count). Without a web snapshot both are `skipped` (`not-applicable`): "PHP web settings unknown: enable the health endpoint so Excubia can read the web SAPI (the CLI uses different ini settings)." New report `details`: `sapi` (always `web`), `ageMinutes`, `isOpcacheEnabled`, `hitRate`, `memoryUsedPercent`, `cachedScripts`, `isValidateTimestampsEnabled` (`php-opcache`) and `directive`, `isEnabled`, `sapi`, `ageMinutes` (`php-production-ini`); SARIF location `composer.json`. Never an ini path or value. All additive (schema versions stay `1`; no config key).

- Six more configuration posture checks (#130), run by `php artisan excubia:check` and `excubia:push` like the #73 ones and `skipped` ("requires Artisan", `not-applicable`) in `vendor/bin/excubia`: `laravel-app-key` (`app.key` empty, in any environment: fail, critical), `laravel-session-security` (in `production`, `session.secure` false while `app.url` is https, or `session.http_only` false: warn, medium, one row per key), `laravel-cors-wildcard` (in `production`, `cors.allowed_origins` contains `*` with `cors.supports_credentials`: fail, high; `*` alone: warn, low), `laravel-production-drivers` (in `production`, queue `sync`, cache `array` / `null`, session `array`, mail `log` / `array`: warn, medium, one row per driver), `laravel-log-level` (in `production`, the default log channel logs at `debug`: warn, low) and `laravel-dev-packages` (in `production`, Telescope, Debugbar, Ray, Pail or Clockwork listed in `composer.json` `require` instead of `require-dev` and enabled in the booted app: warn, medium, one row per package). Findings name the config key and the problem, never the value. New `details`: `laravel-cors-wildcard` `hasCredentials`, `laravel-production-drivers` `component`, `driver`, `laravel-dev-packages` `package`, documented in `docs/report-schema.json`. SARIF locations `config/app.php`, `config/session.php`, `config/cors.php`, `config/logging.php` and `composer.json`. Additive: new check ids registered after the existing ones, optional `details`; `schemaVersion` stays `1`.
- Release identifier and deploy markers (#129), all additive (schema and protocol versions stay `1`): an optional `release` on the JSON report and push payload, on runtime batches (`runtime.release`) and on exception batches (`exceptions.release`; the group fingerprint does not change). It is resolved from the new `excubia.json` key `release`, the new environment variable `EXCUBIA_RELEASE`, then `GITHUB_SHA`, `CI_COMMIT_SHA`, `VERCEL_GIT_COMMIT_SHA`, `FORGE_DEPLOY_COMMIT`, `LARAVEL_CLOUD_COMMIT`, and for the standalone CLI the commit in the project's `.git` (read from `HEAD` and the ref file or `packed-refs`, without running `git`). Up to 100 characters of `[A-Za-z0-9._+/@-]`, otherwise `null`. New option `--deploy` on `push` and `excubia:push` adds `deployedAt` to the report so excubia-app can draw a deploy marker; the CI and excubia-app guides show it as the post-deploy step.
- New check `dependency-licenses` (#134), in the standalone CLI and in Artisan: a license inventory of the locked Composer and npm packages, read from the `license` entries of `composer.lock` and `package-lock.json` (lockfileVersion 2 and 3) without any request. A license in `checks.dependency-licenses.denied` fails at high, a strong copyleft license (GPL, AGPL, SSPL, EUPL, OSL, RPL, Sleepycat) warns at medium, a missing or unknown license warns at low; `allowed` licenses never warn. SPDX expressions are read with `OR`, `AND`, parentheses, `WITH` and the `+` / `-only` / `-or-later` suffixes, so `MIT OR GPL-3.0-only` passes. New `excubia.json` keys `checks.dependency-licenses.allowed`, `.denied` (SPDX ids or globs) and `.includeDev` (default `false`). Finding `details`: `package`, `lockedVersion`, `licenses`, `ecosystem`. New optional top-level report field `licenses` with the counts per license id and per ecosystem (`composer`, `npm`). SARIF results point at the package's lockfile. All additive: `schemaVersion` and the schemas' `x-excubia-version` stay `1`; the check id is appended to the run order, so every existing check id keeps its position.
- Seven more runtime aggregate types (#132), each off by default with its own `runtime.<type>.enabled` and `sampleRate` (new `excubia.json` keys `runtime.requestMemory`, `jobMemory`, `queueWait`, `cache`, `mail`, `notifications`, `logLevels`): `requestMemory` (peak MB per route name and method), `jobMemory` (peak MB per job class and queue; the PHP peak is reset when a job starts), `queueWait` (ms between push and first attempt, without the delay, from an `excubiaQueuedAt` timestamp added to job payloads or Horizon's `pushedAt`), `cache` (hits, misses, writes and deletes per store and key prefix cut at the first `:` or `.`, masked, `[masked]` when it still looks like an id or token), `mail` (sent per mailable and mailer; failed only when exception capture sees a reported Symfony Mailer transport exception, since Laravel has no mail failure event), `notification` (sent and failed per class and channel) and `logLevel` (count per level; `MessageLogged` has no channel, and the message and context are never read). New aggregate metric fields `totalMb`, `maxMb`, `hits`, `misses`, `writes`, `deletes`, documented in `docs/runtime-schema.json` with a rule for apps: accept a batch with an unknown type and skip those entries. Additive: the five existing types and their defaults are unchanged; `x-excubia-version` and `protocolVersion` stay `1`. The overhead benchmark now runs with every type on.
- Infrastructure health checks (#131), as in spatie/laravel-health and Oh Dear, run by `php artisan excubia:check` and `excubia:push` and `skipped` ("requires Artisan") in `vendor/bin/excubia`: `laravel-database` (`select 1` on the default connection and on `checks.laravel-database.connections`: fail, critical, one row per connection; a connection opened for the probe gets a 3 s connect timeout and is closed again), `laravel-cache` (write, read and delete a random probe key on the default store: fail, high; skipped with the `null` driver), `laravel-storage` (`storage` or `bootstrap/cache` not writable: fail, high), `laravel-disk-space` (disk holding `storage/` at least 80 % used: warn, medium; at least 90 %: fail, high) and `laravel-queue-backlog` (oldest pending job older than 15 minutes or more than 1000 pending, per queue, `database` and `redis` drivers only: warn, medium). ### Security

- Private package names are no longer sent to Packagist, OSV.dev or GitHub (#108). A Composer package is checked only when its `composer.lock` entry has Packagist's `notification-url` and no `path` or `artifact` dist (path, artifact, VCS, Satis and Private Packagist packages are private); an npm package only when `resolved` is on `https://registry.npmjs.org/` and it is not a link (`file:`, VCS, workspace and other-registry packages are private). `composer-advisories`, `npm-advisories`, `composer-abandoned`, `composer-stale` and `laravel-next-blocker` report them in one `skipped` row with subject `private packages`, `skipReason` `not-applicable` and the skipped names in the message, so such a check can show `skipped` instead of `pass`; the exit code and `--strict` are unchanged.
- Threat model of every outgoing and stored data path: `docs/SECURITY-MODEL.md` (#82). `SECURITY.md` names the supported versions for 1.x.
- The default response cache directory is per user (`<temp>/qiick-excubia-<uid>`) and is skipped when it is a symlink, owned by another user or writable by group or others, so another local user cannot plant responses that hide advisories. `cache:clear` deletes only files named like cache entries.
- `push` and `excubia:push-runtime` no longer follow redirects: a 3xx from the app is an error, so the envelope is never resent to another host or over plain HTTP.
- URL credentials (`https://user:password@…`) are removed from the app URL in error messages and in the `-v` request list.
- Exception masking also covers `'key' => 'value'` dumps, quoted values with spaces, unterminated quotes and the `pass`, `cookie`, `session`, `dsn` and `private_key` key names.
- Scheduled task names in runtime data go through the same masks, so `--password=…` and similar arguments are not buffered or sent.
- Scheduled task names in runtime data (#109) drop every argument: an Artisan command is `artisan <command name>` and an `exec()` task is the executable's file name (leading `VAR=value` assignments skipped), so secrets in forms no mask recognises (`-pSECRET`, positional arguments) are never buffered or sent, and arguments no longer create new aggregates. A task description set by the developer is kept, masked as before. This changes the documented `task` value in `docs/runtime-schema.json` and SPEC §7.
- GitHub owner and repository names `.` and `..` are refused before a request is built.
- The GitHub Action (#111) installs Excubia's dependencies from a committed lock (`.github/action-install/composer.lock`, resolved for PHP 8.2) instead of resolving them on every run, with `--no-plugins --no-scripts`. A test keeps the lock in sync with `composer.json`, and `.github/workflows/action-test.yml` also runs the action on PHP 8.2.
- `check`, `push`, `excubia:check`, `excubia:push` and `excubia:push-runtime` print one warning on stderr when `app.token` is set in `excubia.json` (#110): "app.token is set in excubia.json; prefer EXCUBIA_APP_TOKEN so the token is not committed." The key keeps working; README, the configuration and push guides and `excubia.schema.json` say the same.
- Slow-query SQL in runtime data and the SQL of captured query exceptions (#106) also replace standalone numbers, hex literals (`0x…`, `X'…'`) and dollar-quoted bodies (`$$…$$`, `$tag$…$tag$`) with `?`, not only single-quoted strings. Placeholders (`$1`, `?`), identifiers such as `t1` and double-quoted or backtick-quoted identifiers stay. This changes the documented `sql` value in `docs/runtime-schema.json` and SPEC §7: queries that differed only by an inline value now share one aggregate.
- Exception masking (#104) also replaces URL hosts and ports and host names after `host:`, `hostname=`, `resolve host` and `getaddrinfo for` with `[host]`, reduces Windows drive paths (`C:\…`, `C:/…`) and UNC paths (`\\server\share\…`) to the file name, masks the whole value of an `Authorization` / `Proxy-Authorization` header for any scheme other than `Bearer` / `Basic` (`Token`, `Digest`, `AWS4-HMAC-SHA256`…), and masks phone-like numbers (`+` and 8 or more digits) and US social security numbers as `[number]`. The masked message text of exception groups changes accordingly.
- Health endpoint (#107): `EXCUBIA_HEALTH_SECRET` must be at least 32 characters; a shorter secret counts as no secret, so the route is not registered, and `excubia:check` / `excubia:push` print a warning on stderr. The route is throttled with Laravel's `ThrottleRequests` middleware at 60 requests a minute per client IP (`429` above it).
